## ЧАСТЬ 1. МЕТОДИЧКА ДЛЯ СТУДЕНТОВ

---
## Цель работы
- **Теоретическая:** Систематизировать типовые неисправности протокола OSPFv2, изучить методику последовательной диагностики (от физического уровня до уровня маршрутизации), научиться читать вывод команд `show ip ospf neighbor`, `show ip ospf interface`, `show ip ospf database`, `show ip route ospf` и интерпретировать состояния соседства.
- **Практическая:** Приобрести навыки поиска и устранения неполадок OSPF в готовой конфигурации маршрутизаторов Cisco в среде Packet Tracer, восстановления соседства и сквозной связности.

---

## Теоретическая справка

**1. Методика диагностики OSPF (снизу вверх):**

Диагностику всегда начинают с нижних уровней и двигаются вверх. Пропуск этапа приводит к «лечению симптома», а не причины.

| Уровень           | Что проверять                                             | Команды                                    |
| ----------------- | --------------------------------------------------------- | ------------------------------------------ |
| 1. Физический     | Кабель подключён, интерфейс `up/up`                       | `show ip interface brief`                  |
| 2. Канальный      | VLAN, trunk, режим порта, дуплекс                         | `show interfaces`, `show interfaces trunk` |
| 3. Сетевой (IP)   | IP-адрес, маска, подсеть на одном линке                   | `show ip interface brief`, `ping` напрямую |
| 4. OSPF-интерфейс | Зона, тип сети, таймеры, аутентификация, MTU, пассивность | `show ip ospf interface <int>`             |
| 5. OSPF-соседство | Состояние соседей, Router ID, приоритеты                  | `show ip ospf neighbor`                    |
| 6. OSPF-база      | Наличие LSA, типы, возраст                                | `show ip ospf database`                    |
| 7. Маршрутизация  | Наличие маршрутов OSPF, метрики, next-hop                 | `show ip route ospf`, `traceroute`         |

**2. Типовые состояния соседства OSPF и их причины:**

| Состояние            | Что означает                                                 | Типичные причины                                                                          |
| -------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| **DOWN**             | Hello не получены                                            | Не включён OSPF на интерфейсе; интерфейс shutdown; несовпадение зоны; пассивный интерфейс |
| **INIT**             | Hello получены, но наш Router ID не указан в ответе          | Односторонняя связь; несовпадение аутентификации; ACL блокирует multicast                 |
| **2-WAY**            | Двусторонняя связь установлена, но полное соседство не нужно | Норма для DROTHER в broadcast-сети; если у всех — значит, нет DR/BDR                      |
| **EXSTART/EXCHANGE** | Идёт обмен DBD, но не завершается                            | **Несовпадение MTU** на интерфейсах; разные версии OSPF                                   |
| **LOADING**          | Запрос недостающих LSA                                       | Нестабильный линк; перегрузка                                                             |
| **FULL**             | Соседство установлено полностью                              | Норма для DR/BDR и P2P                                                                    |

**3. Типовые ошибки конфигурации OSPF:**

| №   | Ошибка                                                                      | Симптом                                                     | Как обнаружить                                             |                                                      |
| --- | --------------------------------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------- |
| 1   | Интерфейсы в **разных зонах**                                               | Соседство DOWN, hello игнорируется                          | `show ip ospf interface` на обоих концах                   |                                                      |
| 2   | **Несовпадение Hello/Dead-таймеров**                                        | Соседство DOWN                                              | `show ip ospf interface` — сравнить таймеры                |                                                      |
| 3   | **Несовпадение аутентификации** (пароль, тип, key ID)                       | Соседство DOWN или INIT                                     | `show ip ospf interface` — проверить метод и ключ          |                                                      |
| 4   | **Несовпадение MTU**                                                        | Соседство застревает в EXSTART/EXCHANGE                     | `show interfaces` — сравнить MTU; `debug ip ospf adj`      |                                                      |
| 5   | **Ошибка в `network`** (неверная маска/wildcard, не та сеть)                | Сеть не анонсируется, сосед не устанавливается              | `show run                                                  | section router ospf`, `show ip ospf interface brief` |
| 6   | **Пассивный интерфейс** на магистральном линке                              | Соседство DOWN                                              | `show ip ospf interface` — «No Hellos (Passive interface)» |                                                      |
| 7   | **Дубликат Router ID**                                                      | Нестабильное соседство, мигание маршрутов                   | `show ip ospf neighbor` — одинаковые Router ID             |                                                      |
| 8   | **Несовпадение типа сети** (broadcast vs point-to-point)                    | Соседство есть, но маршруты не те; DR/BDR там, где не нужно | `show ip ospf interface` — тип сети                        |                                                      |
| 9   | **ACL блокирует OSPF** (224.0.0.5/6, протокол 89)                           | Соседство DOWN при рабочем пинге                            | `show ip access-lists`, `show ip interface`                |                                                      |
| 10  | **Неверный `passive-interface` по умолчанию** (`passive-interface default`) | Часть соседей не поднимается                                | `show ip ospf interface`                                   |                                                      |

**4. Ключевые команды диагностики:**
```
show ip interface brief
show ip ospf neighbor
show ip ospf neighbor detail
show ip ospf interface
show ip ospf interface brief
show ip ospf database
show ip route ospf
show running-config | section router ospf
show ip protocols
debug ip ospf adj        ! использовать с осторожностью
debug ip ospf hello
```

## Задание

**1. Исходные данные**

Преподаватель выдаёт готовый файл Packet Tracer с собранной топологией и предварительно настроенными маршрутизаторами. В конфигурации **намеренно допущены ошибки OSPF**. Сеть работает нестабильно: часть соседства не устанавливается, отдельные сети недоступны, пинги теряются.

**Схема адресации (эталонная, для проверки):**

| Устройство | Интерфейс | IP / маска                       | Зона |
| ---------- | --------- | -------------------------------- | ---- |
| R1         | G0/0      | 10.0.123.1/24                    | 0    |
| R1         | G0/1      | 10.0.12.1/30                     | 0    |
| R1         | G0/2      | 192.168.1.1/24                   | 0    |
| R2         | G0/0      | 10.0.123.2/24                    | 0    |
| R2         | G0/1      | 10.0.12.2/30                     | 0    |
| R2         | G0/2      | 10.0.24.1/30                     | 0    |
| R3         | G0/0      | 10.0.123.3/24                    | 0    |
| R3         | G0/1      | 10.0.34.1/30                     | 0    |
| R3         | G0/2      | 192.168.3.1/24                   | 0    |
| R4         | G0/0      | 10.0.34.2/30                     | 0    |
| R4         | G0/1      | 10.0.24.2/30                     | 0    |
| R4         | G0/2      | 192.168.4.1/24                   | 0    |
| PC1        | —         | 192.168.1.100/24, GW 192.168.1.1 | —    |
| PC2        | —         | 192.168.2.100/24, GW 192.168.2.1 | —    |
| PC3        | —         | 192.168.3.100/24, GW 192.168.3.1 | —    |
| PC4        | —         | 192.168.4.100/24, GW 192.168.4.1 | —    |

**Примечание:** R1, R2, R3 подключены к SW1 (общий broadcast-сегмент 10.0.123.0/24). R1–R2 также соединены напрямую (10.0.12.0/30). R3–R4 (10.0.34.0/30), R4–R2 (10.0.24.0/30) — P2P-линки.

**2. Порядок выполнения**

**Этап 1. Фиксация симптомов**
1. Откройте выданный файл Packet Tracer.
2. Выполните пинг с PC1 до PC2, PC3, PC4. Зафиксируйте, какие узлы недоступны и какие потери.
3. На каждом маршрутизаторе выполните:
   ```
   show ip interface brief
   show ip ospf neighbor
   show ip ospf interface brief
   ```
4. Занесите в таблицу: какие соседства отсутствуют, в каком состоянии находятся имеющиеся.

**Этап 2. Локализация неисправностей**
1. Для каждой пары маршрутизаторов, где нет соседства, проверьте:
   - Находятся ли интерфейсы в одной подсети (`show ip interface brief`);
   - В одной ли зоне OSPF (`show ip ospf interface <int>`);
   - Совпадают ли Hello/Dead-таймеры;
   - Совпадает ли метод аутентификации и ключ;
   - Совпадает ли MTU (`show interfaces`);
   - Не является ли интерфейс пассивным;
   - Нет ли ACL, блокирующего OSPF.
2. Для маршрутизаторов, где соседство есть, но сеть недоступна, проверьте:
   - `show ip ospf database` — есть ли LSA о нужной сети;
   - `show ip route ospf` — есть ли маршрут;
   - `show running-config | section router ospf` — корректны ли `network`.
3. При необходимости используйте `debug ip ospf adj` на проблемном маршрутизаторе (включать точечно, не забывать выключать `undebug all`).

**Этап 3. Устранение неисправностей**
1. Исправьте обнаруженные ошибки. После каждого исправления:
   ```
   clear ip ospf process
   show ip ospf neighbor
   ```
2. Добейтесь следующего состояния:
   - Все соседства в состоянии **FULL** (в broadcast-сети R1/R2/R3 — FULL с DR/BDR, 2-WAY между DROTHER);
   - `show ip route ospf` на каждом маршрутизаторе содержит все удалённые сети;
   - Пинг между всеми ПК проходит без потерь.

**Этап 4. Проверка результата**
1. Выполните `show ip ospf neighbor` на всех маршрутизаторах — убедитесь в полном соседстве.
2. Выполните `show ip route ospf` — убедитесь в наличии всех маршрутов.
3. Проверьте сквозную связность PC1 → PC2, PC1 → PC3, PC1 → PC4. Выполните `tracert` и зафиксируйте пути.
4. Заполните таблицу «до/после» в отчёте.

## Контрольные вопросы

1. Почему диагностику OSPF начинают с проверки `show ip interface brief`, а не с `show ip ospf neighbor`?
2. Что означает состояние соседства **INIT**? Чем оно отличается от **2-WAY**?
3. В каком состоянии застревает соседство при несовпадении MTU и почему?
4. Какие параметры OSPF **обязаны** совпадать на двух концах линка для установления соседства?
5. Что произойдёт, если на двух маршрутизаторах одинаковый Router ID? Как это обнаружить?
