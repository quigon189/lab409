## Цель работы
- **Теоретическая:** Изучить особенности работы OSPFv2 в сетях множественного доступа (broadcast multi-access), механизм выбора DR/BDR, влияние приоритета интерфейса и Router ID на выбор выделенных маршрутизаторов, а также формирование соседских отношений между DROTHER-маршрутизаторами.
- **Практическая:** Приобрести навыки настройки OSPFv2 на интерфейсах, подключённых к общему сегменту Ethernet, управления выбором DR/BDR, настройки пассивных интерфейсов и аутентификации, а также анализа соседства и базы данных LSDB в Cisco Packet Tracer.

---

## Теоретическая справка

**1. Основные термины и определения:**
- **Сеть множественного доступа (multi-access)** — сегмент сети, к которому подключено более двух маршрутизаторов (например, общий коммутатор Ethernet). В OSPF такие сети по умолчанию имеют тип **broadcast**.
- **DR (Designated Router)** — выделенный маршрутизатор, который формирует LSA Type 2 (Network LSA) для описания сегмента множественного доступа и устанавливает полное соседство (Full) со всеми остальными маршрутизаторами сегмента.
- **BDR (Backup Designated Router)** — резервный выделенный маршрутизатор. Устанавливает полное соседство со всеми и принимает роль DR при его отказе.
- **DROTHER** — все остальные маршрутизаторы сегмента. Они устанавливают полное соседство только с DR и BDR, а между собой остаются в состоянии **2-WAY** (обмениваются Hello, но не синхронизируют LSDB напрямую).
- **Приоритет интерфейса OSPF (`ip ospf priority`)** — параметр от 0 до 255 (по умолчанию 1). Чем выше приоритет, тем больше шансов стать DR. Приоритет 0 означает, что маршрутизатор не участвует в выборе DR/BDR.
- **Router ID** — уникальный идентификатор маршрутизатора в формате IP-адреса. При выборе DR/BDR при равных приоритетах побеждает маршрутизатор с наибольшим Router ID.
- **Пассивный интерфейс (`passive-interface`)** — интерфейс, на котором OSPF не отправляет Hello-пакеты, но сеть продолжает анонсироваться в LSDB. Применяется для интерфейсов, подключённых к конечным устройствам.

**2. Особенности OSPF в broadcast-сетях:**
- По умолчанию на Ethernet-интерфейсах OSPF использует тип сети **broadcast**. Hello-пакеты отправляются на multicast-адрес `224.0.0.5`.
- Таймеры по умолчанию: Hello — 10 секунд, Dead — 40 секунд.
- Выбор DR/BDR происходит при включении OSPF на интерфейсе или при сбросе процесса OSPF. **Выбор не происходит при добавлении нового маршрутизатора в уже работающий сегмент** — новый участник принимает существующие роли, пока не произойдёт перевыборы.
- DR генерирует **LSA Type 2 (Network LSA)**, в котором перечислены все маршрутизаторы сегмента, включая DR.
- Для принудительного перевыбора DR/BDR используется команда `clear ip ospf process`.

**3. Команды для настройки:**
- Включение OSPF и настройка Router ID:
  ```
  router ospf 1
   router-id 1.1.1.1
   network 10.0.10.0 0.0.0.255 area 0
  ```
- Изменение приоритета на интерфейсе:
  ```
  interface g0/0
   ip ospf priority 100
  ```
- Настройка пассивного интерфейса:
  ```
  router ospf 1
   passive-interface g0/1
  ```
- Аутентификация clear-text:
  ```
  interface g0/0
   ip ospf authentication
   ip ospf authentication-key SECRET_PASS

  router ospf 1
   area 0 authentication
  ```
- Проверка:
  - `show ip ospf neighbor` — состояния соседей (Full, 2-WAY);
  - `show ip ospf interface g0/0` — роль DR/BDR/DROTHER, приоритет, таймеры;
  - `show ip ospf database` — LSDB, наличие LSA Type 2;
  - `show ip route ospf` — маршруты OSPF.

## Задание

### **Обязательная часть**

**1. Построение топологии:**
- Постройте топологию согласно приложенной схеме.
- Разместите 4 маршрутизатора (R1–R4), 1 коммутатор (SW1) и 4 ПК (PC1–PC4).
- Подключите интерфейсы **GigabitEthernet0/0** всех маршрутизаторов к портам коммутатора SW1 (Fa0/1–Fa0/4). Таким образом, все четыре маршрутизатора находятся в **общем broadcast-сегменте**.
- Подключите ПК к интерфейсам **GigabitEthernet0/1** соответствующих маршрутизаторов:
  - PC1 → R1 (G0/1);
  - PC2 → R2 (G0/1);
  - PC3 → R3 (G0/1);
  - PC4 → R4 (G0/1).

**2. Базовая IP-адресация:**

| Устройство | Интерфейс | IP-адрес / маска                   | Назначение        |
| ---------- | --------- | ---------------------------------- | ----------------- |
| R1         | G0/0      | 10.0.10.1/24                       | Broadcast-сегмент |
| R1         | G0/1      | 192.168.1.1/24                     | Сеть PC1          |
| R1         | Loopback0 | 1.1.1.1/32                         | Router ID         |
| R2         | G0/0      | 10.0.10.2/24                       | Broadcast-сегмент |

| R2         | Loopback0 | 2.2.2.2/32                         | Router ID         |

| R3         | G0/1      | 192.168.3.1/24                     | Сеть PC3          |

**3. Настройка OSPF на R1–R4 (Area 0):**
- На каждом маршрутизаторе настройте OSPF с уникальным Router ID и включите в область 0 все сети (broadcast-сегмент, LAN и loopback):
  ```
  ! R1
  router ospf 1
   router-id 1.1.1.1
   network 10.0.10.0 0.0.0.255 area 0
   network 192.168.1.0 0.0.0.255 area 0
   network 1.1.1.1 0.0.0.0 area 0

  ! R2 — аналогично с router-id 2.2.2.2 и сетями 10.0.10.0/24, 192.168.2.0/24, 2.2.2.2/32
  ! R3 — router-id 3.3.3.3, сети 10.0.10.0/24, 192.168.3.0/24, 3.3.3.3/32
  ! R4 — router-id 4.4.4.4, сети 10.0.10.0/24, 192.168.4.0/24, 4.4.4.4/32
  ```
- Настройте **пассивные интерфейсы** для LAN-сетей (G0/1), чтобы Hello-пакеты не отправлялись в сторону ПК:
  ```
  router ospf 1
   passive-interface g0/1
  ```

**4. Наблюдение за выбором DR/BDR (первый этап):**
- Дождитесь установления соседства (около 40 секунд).
- На каждом маршрутизаторе выполните:
  ```
  show ip ospf neighbor
  show ip ospf interface g0/0
  ```
- Зафиксируйте:
  - Кто стал **DR**, кто **BDR**, кто **DROTHER**;
  - Какие состояния соседства (`FULL`, `2-WAY`);
  - Обратите внимание: DROTHER-маршрутизаторы должны быть в состоянии `2-WAY` друг с другом, но `FULL` с DR и BDR.

**5. Управление выбором DR/BDR (второй этап):**
- На R1 на интерфейсе G0/0 установите приоритет 100:
  ```
  interface g0/0
   ip ospf priority 100
  ```
- На R2 установите приоритет 50:
  ```
  interface g0/0
   ip ospf priority 50
  ```
- На R3 и R4 оставьте приоритет по умолчанию (1).
- Сбросьте процесс OSPF на всех маршрутизаторах для принудительного перевыбора:
  ```
  clear ip ospf process
  ```
  (подтвердите `yes`).
- Снова выполните:
  ```
  show ip ospf neighbor
  show ip ospf interface g0/0
  ```
- Убедитесь, что **R1 стал DR**, **R2 — BDR**, а R3 и R4 — DROTHER.

**6. Настройка аутентификации OSPF (clear-text) в broadcast-сегменте:**
- На R1–R4 на интерфейсе G0/0:
  ```
  interface g0/0
   ip ospf authentication
   ip ospf authentication-key SECRET_OSPF_PASS
  ```
- В процессе OSPF:
  ```
  router ospf 1
   area 0 authentication
  ```
- Убедитесь, что соседство не потерялось. Попробуйте изменить пароль на одном маршрутизаторе — соседство должно разорваться, а после возврата пароля — восстановиться.

**7. Проверка базы данных LSDB:**
- На R1 (DR) выполните:
  ```
  show ip ospf database
  ```
- Найдите **LSA Type 2 (Network LSA)** для сегмента 10.0.10.0/24. Убедитесь, что в нём перечислены все четыре маршрутизатора.
- Обратите внимание на **LSA Type 1** от каждого маршрутизатора.

**8. Проверка сквозной связности:**
- С PC1 (192.168.1.100) выполните `ping` до PC4 (192.168.4.100). Убедитесь, что пинг проходит без потерь.
- Выполните `tracert` с PC1 до PC4 и зафиксируйте путь (он должен проходить через broadcast-сегмент).

### **Порядок выполнения**
1. Соберите топологию в Cisco Packet Tracer.
2. Настройте IP-адресацию на всех интерфейсах и ПК.
3. Настройте OSPF в Area 0 на R1–R4 с уникальными Router ID и пассивными интерфейсами.
4. Пронаблюдайте выбор DR/BDR по умолчанию.
5. Измените приоритеты на R1 и R2, сбросьте процесс OSPF и проверьте новый выбор DR/BDR.
6. Настройте аутентификацию clear-text и проверьте её влияние на соседство.
7. Проанализируйте LSDB (наличие LSA Type 2).
8. Проверьте сквозную связность.
9. Оформите отчёт.
