## Цель работы
- **Теоретическая:** Изучить принципы работы технологии EtherChannel (агрегация каналов), различия между протоколами LACP, PAgP и статической агрегацией, а также методы балансировки трафика по агрегированным линкам.
- **Практическая:** Приобрести навыки настройки двух агрегированных каналов (по два физических линка в каждом) между двумя коммутаторами для передачи трафика разных VLAN, проверки работоспособности агрегации и анализа распределения нагрузки.

---

## Теоретическая справка

**1. Основные термины и определения:**
- **EtherChannel** — технология агрегации нескольких физических линков в один логический канал. Позволяет увеличить пропускную способность и обеспечить резервирование без использования STP-блокировки.
- **Port-Channel (Po)** — логический интерфейс, объединяющий физические порты. Настраивается как обычный порт (access/trunk).
- **LACP (Link Aggregation Control Protocol, IEEE 802.3ad)** — открытый стандартный протокол агрегации. Режимы: `active` (активно предлагает агрегацию) и `passive` (отвечает на предложения).
- **PAgP (Port Aggregation Protocol)** — проприетарный протокол Cisco. Режимы: `desirable` (активно предлагает) и `auto` (пассивно отвечает).
- **Статическая агрегация (mode on)** — агрегация без протокола согласования. Используется только между устройствами, поддерживающими EtherChannel, требует ручной настройки с обеих сторон.
- **Балансировка нагрузки** — распределение трафика между физическими линками в агрегированном канале. Методы: по MAC-адресу источника/назначения, по IP-адресу источника/назначения, по комбинации (src-dst-ip, src-dst-mac и т.д.).

**2. Базовые принципы:**
- Все физические порты в одном EtherChannel должны иметь **одинаковые параметры**: скорость, дуплекс, режим (access/trunk), разрешённые VLAN, native VLAN.
- При агрегации физические линки рассматриваются STP как **один логический линк**. STP не блокирует избыточные порты внутри EtherChannel.
- При обрыве одного из физических линков трафик автоматически перераспределяется по оставшимся, что обеспечивает отказоустойчивость.
- **Ограничения Cisco 2960:** до 6 EtherChannel-групп, до 8 портов в каждой (в Packet Tracer обычно 4–8).
- Для балансировки трафика на коммутаторах Cisco 2960 используется метод `src-mac` по умолчанию (можно изменить глобально командой `port-channel load-balance`).

**3. Команды для настройки:**
- Создание EtherChannel (LACP):
  ```
  interface range fa0/1-2
  channel-group 1 mode active
  ```
- Создание EtherChannel (PAgP):
  ```
  interface range fa0/1-2
  channel-group 1 mode desirable
  ```
- Создание статического EtherChannel:
  ```
  interface range fa0/1-2
  channel-group 1 mode on
  ```
- Настройка логического интерфейса:
  ```
  interface port-channel 1
  switchport mode trunk
  switchport trunk allowed vlan 10
  ```
- Проверка:
  - `show etherchannel summary` — сводка по всем группам;
  - `show etherchannel port-channel` — детали;
  - `show etherchannel load-balance` — текущий метод балансировки;
  - `show interfaces port-channel <n>` — состояние логического интерфейса.

## Задание

### 1. Обязательная часть

**1. Построение топологии:**
- Разместите два коммутатора: SW1 и SW2.
- Соедините их **четырьмя** прямыми кабелями:
  - Fa0/1 ↔ Fa0/1
  - Fa0/2 ↔ Fa0/2
  - Fa0/3 ↔ Fa0/3
  - Fa0/4 ↔ Fa0/4
- Подключите ПК:
  - К SW1: ПК1 (VLAN 10) — порт Fa0/10, ПК2 (VLAN 20) — порт Fa0/11;
  - К SW2: ПК3 (VLAN 10) — порт Fa0/10, ПК4 (VLAN 20) — порт Fa0/11.

**2. Настройка VLAN на обоих коммутаторах:**
```
vlan 10
 name Users
vlan 20
 name Servers
```

**3. Настройка access-портов для ПК:**
```
! На SW1
interface fa0/10
 switchport mode access
 switchport access vlan 10
interface fa0/11
 switchport mode access
 switchport access vlan 20

! На SW2 — аналогично
interface fa0/10
 switchport mode access
 switchport access vlan 10
interface fa0/11
 switchport mode access
 switchport access vlan 20
```

**4. Настройка первого EtherChannel (Po1, VLAN 10) с LACP:**
```
! На SW1
interface range fa0/1-2
 switchport mode trunk
 channel-group 1 mode active

interface port-channel 1
 switchport mode trunk
 switchport trunk allowed vlan 10

! На SW2 — то же самое
interface range fa0/1-2
 switchport mode trunk
 channel-group 1 mode active

interface port-channel 1
 switchport mode trunk
 switchport trunk allowed vlan 10
```

**5. Настройка второго EtherChannel (Po2, VLAN 20) с LACP:**
```
! На SW1
interface range fa0/3-4
 switchport mode trunk
 channel-group 2 mode active

interface port-channel 2
 switchport mode trunk
 switchport trunk allowed vlan 20

! На SW2 — то же самое
interface range fa0/3-4
 switchport mode trunk
 channel-group 2 mode active

interface port-channel 2
 switchport mode trunk
 switchport trunk allowed vlan 20
```

**6. Проверка агрегации:**
- На обоих коммутаторах выполните:
  ```
  show etherchannel summary
  ```
  Убедитесь, что в группе 1 — два порта в состоянии `P` (in port-channel), флаг `SU` (in use), протокол `LACP`. Аналогично для группы 2.
- Выполните:
  ```
  show etherchannel port-channel
  show interfaces port-channel 1
  show interfaces port-channel 2
  ```
- Проверьте состояние trunk:
  ```
  show interfaces trunk
  ```
  Убедитесь, что Po1 пропускает только VLAN 10, Po2 — только VLAN 20.

**7. Настройка ПК:**
- ПК1 (VLAN 10): `192.168.10.10/24`, шлюз — не требуется (в пределах одного VLAN);
- ПК3 (VLAN 10): `192.168.10.11/24`;
- ПК2 (VLAN 20): `192.168.20.10/24`;
- ПК4 (VLAN 20): `192.168.20.11/24`.

**8. Проверка связности:**
- С ПК1 (VLAN 10) пингуйте ПК3 (VLAN 10) — должно проходить без потерь.
- С ПК2 (VLAN 20) пингуйте ПК4 (VLAN 20) — должно проходить без потерь.
- Обратите внимание: ПК1 не должен пинговаться с ПК2, так как между VLAN нет маршрутизации.

**9. Проверка балансировки нагрузки:**
- Выполните:
  ```
  show etherchannel load-balance
  ```
  По умолчанию используется `src-mac`. Измените метод на `src-dst-ip`:
  ```
  port-channel load-balance src-dst-ip
  ```
- Проверьте, что метод применился.

**10. Тестирование отказоустойчивости:**
- Отключите один физический линк внутри Po1 (например, Fa0/1 на SW1).
- Выполните `show etherchannel summary` — убедитесь, что Po1 остался в работе (флаг `SU`), но в нём теперь один активный порт (флаг `P`).
- Проверьте пинг между ПК1 и ПК3 — должен проходить без потерь.
- Восстановите линк. Убедитесь, что порт вернулся в EtherChannel автоматически.

### 2. Порядок выполнения
2. Соберите топологию в Cisco Packet Tracer.
3. Настройте VLAN и access-порты.
4. Настройте EtherChannel Po1 (VLAN 10) и Po2 (VLAN 20) с LACP.
5. Проверьте агрегацию командами `show etherchannel`.
6. Настройте IP-адреса на ПК.
7. Проверьте связность и балансировку.
8. Проведите тест отказоустойчивости.
9. Оформите отчёт.
