## Цель работы
- **Теоретическая:** Изучить типовые ошибки конфигурации протокола Spanning Tree Protocol (STP), их влияние на топологию коммутируемой сети и методы диагностики с помощью команд Cisco IOS.
- **Практическая:** Приобрести навыки поиска и устранения неисправностей STP в готовой конфигурации коммутаторов с использованием команд `show spanning-tree`, `show interface`, `show logging` и анализа BPDU.

---

## Теоретическая справка

**1. Основные термины и определения:**
- **STP (Spanning Tree Protocol)** — протокол, предотвращающий образование петель в коммутируемой сети путём блокировки избыточных портов. Строит логическое дерево без петель.
- **Корневой мост (Root Bridge)** — коммутатор, выбранный в качестве корня дерева STP. Выбор происходит по наименьшему Bridge ID (приоритет + MAC-адрес).
- **BPDU (Bridge Protocol Data Unit)** — служебный кадр, которым коммутаторы обмениваются для построения дерева STP и обнаружения изменений топологии.
- **PortFast** — функция, переводящая порт в состояние Forwarding немедленно. Применяется только на портах, подключённых к конечным устройствам.
- **BPDU Guard** — защитный механизм, отключающий порт при получении BPDU. Предотвращает подключение несанкционированных коммутаторов.
- **PVID (Port VLAN ID)** — VLAN, назначенный на порт коммутатора. Несоответствие PVID между соседними портами вызывает ошибку STP.

**2. Типовые ошибки конфигурации STP:**

| №   | Тип ошибки                             | Причина                                                                      | Симптом                                                         | Как обнаружить                                       |
| --- | -------------------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------- |
| 1   | Неправильный корневой мост             | Приоритет выше, чем у коммутатора доступа; отсутствие `root primary` на ядре | Трафик идёт через коммутатор доступа, STP неоптимален           | `show spanning-tree` — корень не тот, что ожидался   |
| 2   | Несоответствие PVID                    | На trunk-портах с обеих сторон разные native VLAN                            | Порт переходит в состояние `inconsistent`, трафик не проходит   | `show spanning-tree inconsistentports`               |
| 3   | PortFast на магистральном порту        | По ошибке включён на trunk-интерфейсе                                        | Порт может уйти в Forwarding, минуя проверки, что создаёт петлю | `show spanning-tree interface` — тип `Edge` на trunk |
| 4   | BPDU Guard на магистральном порту      | Включён на порту между коммутаторами                                         | Порт отключается при получении BPDU от соседнего коммутатора    | `show interface status` — `err-disable`              |
| 5   | Несоответствие режимов STP             | На одном коммутаторе `pvst`, на другом — `rapid-pvst`                        | Возможны проблемы совместимости, длительная сходимость          | `show spanning-tree summary` — режим отличается      |
| 6   | Несоответствие дуплекса                | На одном порту `full`, на другом `half`                                      | Позднее обнаружение коллизий, потери BPDU, петля                | `show interface` — `duplex mismatch`                 |
| 7   | Отсутствие BPDU Guard на access-портах | Не настроен на портах конечных устройств                                     | Подключение несанкционированного коммутатора создаёт петлю      | `show spanning-tree summary` — BPDU Guard disabled   |

**3. Команды диагностики:**
- `show spanning-tree` — общее состояние STP.
- `show spanning-tree vlan <id>` — состояние для конкретного VLAN.
- `show spanning-tree interface <int>` — состояние порта (роль, статус, тип).
- `show spanning-tree summary` — сводка: режим, корень, состояние PortFast/BPDU Guard.
- `show spanning-tree inconsistentports` — список портов с ошибками STP.
- `show interface status` — состояние портов (включая `err-disable`).
- `show logging` — журнал событий (срабатывание BPDU Guard, изменения топологии).

## Задание

**1. Исходные данные**

Скачайте готовый файл Packet Tracer с собранной топологией и предварительно настроенными коммутаторами. В конфигурации **намеренно допущены ошибки STP**. Сеть может работать нестабильно: наблюдаются потери пакетов, длительная сходимость, отдельные сегменты недоступны.

**2. Порядок выполнения**

**Этап 1. Базовая диагностика**
1. Откройте выданный файл Packet Tracer.
2. Проверьте связность: выполните `ping` между ПК в одном VLAN. Зафиксируйте, какие узлы недоступны и какие потери наблюдаются.
3. На каждом коммутаторе выполните:
   ```
   show spanning-tree summary
   show spanning-tree
   show interface status
   ```
4. Запишите в отчёт: какой коммутатор является корневым, какие порты в состоянии `blocking`, есть ли порты в состоянии `err-disable` или `inconsistent`.

**Этап 2. Поиск ошибок**
1. Изучите вывод `show spanning-tree summary`. Сравните корневой мост с ожидаемым (ядро SW1).
2. Проверьте `show spanning-tree inconsistentports` на всех коммутаторах.
3. Проверьте `show interface status` — найдите порты в состоянии `err-disable` или `down`.
4. Проверьте `show logging` — найдите записи о срабатывании BPDU Guard, изменениях топологии, ошибках STP.
5. Проверьте дуплекс и скорость на всех магистральных интерфейсах:
   ```
   show interface <int>
   ```
6. Проверьте режим STP на всех коммутаторах:
    ```
    show spanning-tree summary | include mode
    ```
7. Проверьте настройки PortFast и BPDU Guard на всех портах:
    ```
    show spanning-tree interface <int> detail
    ```

**Этап 3. Устранение ошибок**
1. Исправьте обнаруженные ошибки согласно выявленным причинам (см. теоретическую справку).
2. После каждого исправления проверяйте результат:
    ```
    show spanning-tree
    show spanning-tree inconsistentports
    show interface status
    ```
3. Добейтесь следующего состояния:
    - Корневым мостом для всех VLAN является SW1 (Core-SW);
    - Все магистральные порты — в состоянии `forwarding` или `blocking` (без `err-disable` и `inconsistent`);
    - PortFast и BPDU Guard включены только на access-портах;
    - Дуплекс и скорость согласованы на всех линках;
    - Режим STP одинаков на всех коммутаторах.

**Этап 4. Проверка результата**
1. Выполните `ping` между ПК в одном VLAN. Убедитесь в отсутствии потерь.
2. Выполните `show spanning-tree` и убедитесь, что топология стабильна.
3. Зафиксируйте в отчёте состояние «до» и «после» для каждого исправления.
