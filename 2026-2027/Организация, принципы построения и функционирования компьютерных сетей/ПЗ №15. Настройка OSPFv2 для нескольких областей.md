## Цель работы
- **Теоретическая:** Изучить принципы построения многообластной архитектуры OSPFv2, назначение магистральной области (Area 0), роли ABR и ASBR, особенности специализированных типов областей (stub, totally stub, NSSA), механизм распространения суммарных маршрутов (LSA Type 3) и внешних маршрутов (LSA Type 5 / Type 7).
- **Практическая:** Приобрести навыки настройки OSPFv2 с несколькими областями в Cisco Packet Tracer, настройки тупиковых и полностью тупиковых областей, области NSSA с редистрибуцией внешнего статического маршрута, а также анализа таблиц маршрутизации и базы LSDB в разных типах областей.

## Теоретическая справка

**1. Основные термины и определения:**
- **Многообластная архитектура OSPF** — разбиение домена OSPF на несколько логических областей (areas) для уменьшения размера LSDB, сокращения служебного трафика и локализации пересчёта топологии (SPF) внутри области.
- **Area 0 (Backbone)** — магистральная область, обязательная при наличии более одной области. Все межобластные маршруты проходят через неё.
- **ABR (Area Border Router)** — маршрутизатор, имеющий интерфейсы в двух и более областях. Формирует суммарные LSA Type 3 при передаче маршрутов между областями.
- **ASBR (Autonomous System Boundary Router)** — маршрутизатор, редистрибутирующий в OSPF внешние маршруты (статические, из других протоколов). Генерирует LSA Type 5 (или Type 7 в NSSA).
- **Stub Area (тупиковая область)** — область, в которую не передаются внешние маршруты (LSA Type 5). Вместо них ABR анонсирует маршрут по умолчанию. ASBR внутри stub-области запрещён.
- **Totally Stubby Area (полностью тупиковая область)** — область, в которую не передаются ни внешние LSA Type 5, ни межобластные LSA Type 3. Только маршрут по умолчанию от ABR. На ABR настраивается `area X stub no-summary`, на внутренних маршрутизаторах — `area X stub`.
- **NSSA (Not-So-Stubby Area)** — область, в которую не передаются LSA Type 5, но разрешён собственный ASBR. Внешние маршруты распространяются внутри NSSA как LSA Type 7 и преобразуются ABR в LSA Type 5 при выходе в Area 0.

**2. Типы LSA в многообластной архитектуре:**

| Тип LSA | Название          | Кто генерирует       | Область распространения                           |
| ------- | ----------------- | -------------------- | ------------------------------------------------- |
| Type 1  | Router LSA        | Каждый маршрутизатор | В пределах своей области                          |
| Type 2  | Network LSA       | DR в broadcast-сети  | В пределах своей области                          |
| Type 3  | Summary LSA       | ABR                  | Между областями                                   |
| Type 4  | ASBR Summary LSA  | ABR                  | В другие области (указывает на ASBR)              |
| Type 5  | External LSA      | ASBR                 | Во все области, кроме stub/totally stub/NSSA      |
| Type 7  | NSSA External LSA | ASBR внутри NSSA     | Только внутри NSSA, преобразуется в Type 5 на ABR |

**3. Ключевые команды настройки:**
- Включение области в OSPF:
  ```
  router ospf 1
   network <сеть> <wildcard> area <id>
  ```
- Настройка stub-области:
  ```
  area 1 stub
  ```
- Настройка totally stubby-области (только на ABR):
  ```
  area 2 stub no-summary
  ```
- Настройка NSSA:
  ```
  area 3 nssa
  ```
- Редистрибуция статического маршрута:
  ```
  ip route 203.0.113.0 255.255.255.0 Null0
  router ospf 1
   redistribute static subnets
  ```
- Пассивные интерфейсы:
  ```
  router ospf 1
   passive-interface g0/1
  ```

**4. Команды проверки:**
- `show ip ospf neighbor` — соседство;
- `show ip ospf interface brief` — принадлежность интерфейсов к областям;
- `show ip route ospf` — маршруты, полученные по OSPF (метки `O`, `O IA`, `O E2`, `O N2`);
- `show ip ospf database` — LSDB (типы LSA);
- `show ip ospf database nssa-external` — Type 7 в NSSA;
- `show ip ospf` — общая информация о процессе, роли ABR/ASBR.

## Контрольные вопросы

1. Почему в многообластной архитектуре OSPF обязательна Area 0? Что произойдёт, если две неблагополучные области соединить напрямую, без магистрали?
2. Какую роль выполняет ABR? Какие типы LSA он генерирует при передаче маршрутов между областями?
3. Чем stub-область отличается от totally stubby? Какие LSA в них блокируются?
4. Почему в stub-области запрещён ASBR, а в NSSA — разрешён? Какой тип LSA используется в NSSA для внешних маршрутов?
5. Каким образом маршрутизатор R3 (stub) узнаёт о существовании сетей за пределами своей области, если внешние LSA в неё не поступают?
