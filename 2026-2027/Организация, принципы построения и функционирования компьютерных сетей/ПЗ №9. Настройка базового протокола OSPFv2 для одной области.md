
**Цель работы**
- **Теоретическая:** Изучить принципы работы протокола динамической маршрутизации OSPFv2, процесс установления соседства (adjacency), выбор DR/BDR в broadcast-сетях, формирование базы данных состояний каналов (LSDB) и типы LSA в пределах одной области (Area 0).
- **Практическая:** Приобрести навыки базовой настройки OSPFv2 в Cisco Packet Tracer на различных типах интерфейсов (broadcast и point-to-point), управления параметрами OSPF (Router ID, reference bandwidth, аутентификация), а также анализа служебного трафика OSPF в режиме симуляции.

---

**Теоретическая справка**

**1. Основные термины и определения:**
- **OSPF (Open Shortest Path First)** — протокол динамической маршрутизации, основанный на алгоритме состояния каналов (Link-State). Маршрутизаторы обмениваются **LSA (Link State Advertisement)** для построения общей **LSDB (Link State Database)**. На основе LSDB по алгоритму Дейкстры вычисляется кратчайший путь до каждой сети.
- **Area (область)** — логическая группировка маршрутизаторов и сетей. В данной работе используется одна область — **Area 0 (backbone)**.
- **Router ID** — уникальный 32-битный идентификатор маршрутизатора в формате IP-адреса. Выбирается вручную или автоматически (наивысший IP на loopback, затем на физическом интерфейсе).
- **Соседство (adjacency)** — состояние, при котором два маршрутизатора обменялись Hello-пакетами и синхронизировали LSDB.
- **DR (Designated Router) и BDR (Backup DR)** — выделенные маршрутизаторы в broadcast-сетях. DR генерирует **LSA Type 2 (Network LSA)** для описания сегмента. Выбор происходит по приоритету интерфейса (`ip ospf priority`), затем по Router ID.
- **Типы сетей OSPF:**
  - **Broadcast** — тип по умолчанию для Ethernet. Выбираются DR/BDR.
  - **Point-to-Point** — DR/BDR не выбираются. На последовательных (Serial) интерфейсах устанавливается по умолчанию; на GigabitEthernet задаётся командой `ip ospf network point-to-point`.
- **Reference Bandwidth** — параметр (по умолчанию 100 Мбит/с) для расчёта метрики: `Metric = Reference BW / Interface BW`. В гигабитных сетях требуется увеличивать (`auto-cost reference-bandwidth 1000`), иначе все гигабитные линки получат одинаковую метрику 1.

**2. Ключевые LSA для Area 0:**
- **LSA Type 1 (Router LSA)** — описывает состояние интерфейсов (линков) маршрутизатора. Генерируется каждым маршрутизатором.
- **LSA Type 2 (Network LSA)** — описывает broadcast-сегмент. Генерируется только DR.

**3. Команды для настройки:**
- Включение OSPF и настройка Router ID:
  ```
  router ospf 1
  router-id 1.1.1.1
  network 10.0.123.0 0.0.0.255 area 0
  auto-cost reference-bandwidth 1000
  ```
- Установка типа сети point-to-point:
  ```
  interface g0/1
  ip ospf network point-to-point
  ```
- Аутентификация (clear-text) на интерфейсе и в зоне:
  ```
  interface g0/0
  ip ospf authentication
  ip ospf authentication-key SECRET_OSPF_PASS

  router ospf 1
  area 0 authentication
  ```
- Проверка:
  - `show ip ospf neighbor` — соседство;
  - `show ip ospf interface <int>` — тип сети, таймеры, роль DR/BDR;
  - `show ip ospf database` — LSDB;
  - `show ip route ospf` — маршруты, полученные по OSPF.

**Задание**

**1. Обязательная часть**

**1. Построение топологии:**
- Разместите 4 маршрутизатора (R1–R4), 1 коммутатор (SW1) и 4 ПК (PC1–PC4).
- Организуйте **broadcast-сегмент**: R1, R2 и R3 подключите к SW1 (порты Fa0/1–Fa0/3 на SW1; на маршрутизаторах используйте интерфейсы GigabitEthernet0/0).
- Организуйте **point-to-point соединения**: R4 подключите к R2 и R3 через интерфейсы GigabitEthernet0/1 и GigabitEthernet0/2 соответственно (в CPT для линков «роутер–роутер» используйте кроссовые кабели).
- Подключите ПК к маршрутизаторам:
  - PC1 → R1 (GigabitEthernet0/1);
  - PC2 → R2 (GigabitEthernet0/2);
  - PC3 → R3 (GigabitEthernet0/1);
  - PC4 → R4 (GigabitEthernet0/0).

**3. Настройка OSPF на R1–R4 (Area 0):**
- На каждом маршрутизаторе включите OSPF с уникальным Router ID:
  ```
  ! R1
  router ospf 1
   router-id 1.1.1.1
   network 10.0.123.0 0.0.0.255 area 0
   network 192.168.1.0 0.0.0.255 area 0
   auto-cost reference-bandwidth 1000

  ! R2
  router ospf 1
   router-id 2.2.2.2
   network 10.0.123.0 0.0.0.255 area 0
   network 10.0.24.0 0.0.0.3 area 0
   network 192.168.2.0 0.0.0.255 area 0
   auto-cost reference-bandwidth 1000

  ! R3
  router ospf 1
   router-id 3.3.3.3
   network 10.0.123.0 0.0.0.255 area 0
   network 10.0.34.0 0.0.0.3 area 0
   network 192.168.3.0 0.0.0.255 area 0
   auto-cost reference-bandwidth 1000

  ! R4
  router ospf 1
   router-id 4.4.4.4
   network 10.0.24.0 0.0.0.3 area 0
   network 10.0.34.0 0.0.0.3 area 0
   network 192.168.4.0 0.0.0.255 area 0
   auto-cost reference-bandwidth 1000
  ```
- **Важно:** на интерфейсах R4 G0/1 и G0/2, а также на R2 G0/1 и R3 G0/1 установите тип сети point-to-point:
  ```
  interface g0/1
   ip ospf network point-to-point
  ```
  Это исключит выбор DR/BDR на данных линках.

**4. Настройка аутентификации OSPF (clear-text) в broadcast-сегменте:**
- На R1, R2, R3 на интерфейсе G0/0:
  ```
  interface g0/0
   ip ospf authentication
   ip ospf authentication-key SECRET_OSPF_PASS
  ```
- В процессе OSPF на R1, R2, R3:
  ```
  router ospf 1
   area 0 authentication
  ```
- Убедитесь, что соседство в broadcast-сегменте устанавливается только при совпадении пароля.

**5. Проверка настройки:**
- Соседство:
  ```
  show ip ospf neighbor
  ```
  Убедитесь, что R1, R2, R3 видят друг друга в broadcast-сегменте; R2 и R3 видят R4 по P2P-линкам.
- Детали OSPF на интерфейсе:
  ```
  show ip ospf interface g0/0
  ```
  Определите, кто стал DR, кто BDR, кто DROTHER. Обратите внимание на тип сети и таймеры.
- База данных LSDB:
  ```
  show ip ospf database
  ```
  Найдите LSA Type 1 (Router LSA) от каждого маршрутизатора и LSA Type 2 (Network LSA) от DR broadcast-сегмента.
- Таблица маршрутизации:
  ```
  show ip route ospf
  ```
  На R4 убедитесь, что маршруты до сетей 192.168.1.0/24, 192.168.2.0/24, 192.168.3.0/24 получены через OSPF.

**6. Анализ служебного трафика OSPF в режиме симуляции:**
- Переключите CPT в режим **Simulation**.
- Отфильтруйте события по протоколу **OSPF**.
- Сбросьте соседство на R1 (`clear ip ospf process` → подтвердить `yes`) и наблюдайте:
  - **Hello-пакеты** — обратите внимание на поля `Network Mask`, `Hello Interval`, `Router Priority`, `Designated Router`, `Backup Designated Router`.
  - **LS Update (LSU)** — раскройте пакет и найдите вложенные **LSA Type 1** (поля `Link Type`, `Link ID`, `Link Data`) и **LSA Type 2** (поле `Network Mask`, список `Attached Router`).
- Зафиксируйте скриншоты для отчёта.

**7. Проверка сквозной связности:**
- С PC1 (192.168.1.100) выполните `ping` до PC4 (192.168.4.100). Убедитесь, что пинг проходит без потерь.
- Выполните `tracert` с PC1 до PC4 и зафиксируйте путь (он должен проходить через broadcast-сегмент и P2P-линк).
