### Цель работы

- **Теоретическая:** Изучить принципы работы протокола Hot Standby Router Protocol (HSRP), назначение виртуального IP-адреса и виртуального MAC-адреса, механизмы выбора активного и резервного маршрутизатора, а также способы балансировки нагрузки между несколькими VLAN с помощью нескольких групп HSRP.
- **Практическая:** Приобрести навыки настройки HSRP на маршрутизаторах (или коммутаторах L3) для обеспечения резервирования шлюза по умолчанию с распределением нагрузки между двумя VLAN.

---

### Теоретическая справка

**1. Основные термины и определения:**
- **HSRP (Hot Standby Router Protocol)** — проприетарный протокол Cisco, обеспечивающий отказоустойчивость шлюза по умолчанию. Несколько маршрутизаторов образуют группу HSRP, один из которых становится **активным (Active)**, остальные — **резервными (Standby)**.
- **Виртуальный IP-адрес** — общий IP-адрес для группы HSRP, который назначается конечным устройствам в качестве шлюза по умолчанию. Конечные устройства не знают, какой физический маршрутизатор является активным.
- **Виртуальный MAC-адрес** — общий MAC-адрес группы HSRP (формат `0000.0c07.acXX`, где XX — номер группы). Активный маршрутизатор отвечает на ARP-запросы, используя этот MAC.
- **Приоритет (Priority)** — параметр, определяющий, какой маршрутизатор станет активным. По умолчанию 100. Чем выше значение, тем больше вероятность стать активным.
- **Preempt (вытеснение)** — команда, позволяющая маршрутизатору с более высоким приоритетом забрать роль активного, если он восстановился после сбоя.
- **Балансировка нагрузки между VLAN** — техника, при которой для разных VLAN назначаются разные активные маршрутизаторы HSRP. Например, для VLAN 10 активным является R1, для VLAN 20 — R2. Это позволяет распределить трафик между устройствами.

**2. Базовые принципы:**
- В одной группе HSRP маршрутизаторы обмениваются **hello-сообщениями** (по умолчанию каждые 3 секунды). Если активный маршрутизатор не отвечает в течение **hold-таймера** (по умолчанию 10 секунд), резервный становится активным.
- Для балансировки нагрузки между двумя VLAN используется **два экземпляра HSRP** (две группы), каждая со своим виртуальным IP-адресом.
- На маршрутизаторе R1 для VLAN 10 настраивается приоритет 110 (Active), для VLAN 20 — приоритет 100 (Standby). На R2 наоборот: для VLAN 10 — 100 (Standby), для VLAN 20 — 110 (Active). Таким образом, R1 обрабатывает трафик VLAN 10, R2 — VLAN 20.
- Если один из маршрутизаторов выходит из строя, второй берёт на себя роль активного для обоих VLAN, обеспечивая непрерывность работы сети.
- **Preempt** необходимо включать на обоих маршрутизаторах, чтобы после восстановления они могли вернуть себе роль активного для «своих» VLAN.

**3. Команды для настройки:**
- Включение HSRP и назначение виртуального IP: `standby <group> ip <virtual-ip>`.
- Назначение приоритета: `standby <group> priority <value>`.
- Включение вытеснения: `standby <group> preempt`.
- Проверка состояния: `show standby`, `show standby brief`.

### Задание

**1. Обязательная часть**

1. **Построение топологии:**
   - Разместите два маршрутизатора: R1 и R2.
   - Разместите два коммутатора: SW1 и SW2.
   - Подключите R1 к SW1 и R2 к SW2 (маршрутизаторы соединяются с коммутаторами).
   - Подключите SW1 и SW2 между собой магистральным линком (trunk).
   - Подключите ПК:
     - К SW1: ПК1 (VLAN 10), ПК2 (VLAN 20);
     - К SW2: ПК3 (VLAN 10), ПК4 (VLAN 20).
   - **Схема подключения маршрутизаторов:** используйте физические интерфейсы GigabitEthernet с подинтерфейсами (router-on-a-stick) для маршрутизации между VLAN.

2. **Настройка VLAN и trunk:**
   - На SW1 и SW2 создайте VLAN 10 и VLAN 20.
   - Настройте access-порты для ПК в соответствующих VLAN.
   - Настройте trunk-порт между SW1 и SW2 с разрешением VLAN 10 и 20.
   - Настройте trunk-порты (или access-порты для подинтерфейсов) на коммутаторах для подключения маршрутизаторов.

3. **Настройка подинтерфейсов на маршрутизаторах:**
   - На R1 создайте подинтерфейс для VLAN 10:
     ```
     interface g0/0.10
     encapsulation dot1Q 10
     ip address 192.168.10.1 255.255.255.0
     ```
   - На R1 создайте подинтерфейс для VLAN 20:
     ```
     interface g0/0.20
     encapsulation dot1Q 20
     ip address 192.168.20.1 255.255.255.0
     ```
   - На R2 создайте аналогичные подинтерфейсы, но с другими физическими IP-адресами:
     ```
     interface g0/1.10
     encapsulation dot1Q 10
     ip address 192.168.10.2 255.255.255.0
     interface g0/1.20
     encapsulation dot1Q 20
     ip address 192.168.20.2 255.255.255.0
     ```

4. **Настройка HSRP с балансировкой нагрузки:**
   - **Для VLAN 10 (группа 10):**
     - На R1 (подинтерфейс `g0/0.10`): приоритет 110, preempt, виртуальный IP `192.168.10.254`.
       ```
       standby 10 ip 192.168.10.254
       standby 10 priority 110
       standby 10 preempt
       ```
     - На R2 (подинтерфейс `g0/1.10`): приоритет 100, preempt, виртуальный IP `192.168.10.254`.
       ```
       standby 10 ip 192.168.10.254
       standby 10 priority 100
       standby 10 preempt
       ```
   - **Для VLAN 20 (группа 20):**
     - На R1 (подинтерфейс `g0/0.20`): приоритет 100, preempt, виртуальный IP `192.168.20.254`.
       ```
       standby 20 ip 192.168.20.254
       standby 20 priority 100
       standby 20 preempt
       ```
     - На R2 (подинтерфейс `g0/1.20`): приоритет 110, preempt, виртуальный IP `192.168.20.254`.
       ```
       standby 20 ip 192.168.20.254
       standby 20 priority 110
       standby 20 preempt
       ```
   - **Пояснение:** для VLAN 10 активным станет R1 (приоритет 110 > 100), для VLAN 20 — R2 (приоритет 110 > 100). Это и есть балансировка нагрузки.

5. **Настройка ПК:**
   - Назначьте ПК статические IP-адреса:
     - ПК1 (VLAN 10): `192.168.10.10/24`, шлюз `192.168.10.254`;
     - ПК2 (VLAN 20): `192.168.20.10/24`, шлюз `192.168.20.254`;
     - ПК3 (VLAN 10): `192.168.10.11/24`, шлюз `192.168.10.254`;
     - ПК4 (VLAN 20): `192.168.20.11/24`, шлюз `192.168.20.254`.

6. **Проверка работы HSRP:**
   - Выполните на R1 и R2:
     ```
     show standby brief
     ```
   - Убедитесь, что для группы 10 на R1 состояние **Active**, на R2 — **Standby**. Для группы 20 — наоборот.
   - Проверьте связность: с ПК1 (VLAN 10) пингуйте ПК3 (VLAN 10), с ПК2 (VLAN 20) — ПК4 (VLAN 20).
   - Выполните трассировку (`tracert`) с ПК1 до ПК3 и с ПК2 до ПК4. Убедитесь, что трафик VLAN 10 идёт через R1, а VLAN 20 — через R2.

7. **Тестирование отказоустойчивости:**
   - В режиме симуляции отключите интерфейс R1, подключённый к SW1 (или выключите R1).
   - Проверьте, что R2 стал активным для VLAN 10 (состояние **Active**).
   - Убедитесь, что связность между ПК1 и ПК3 не нарушилась (пинг продолжает проходить, возможно, с кратковременной потерей 1–2 пакетов).
   - Восстановите R1. Убедитесь, что благодаря `preempt` он снова стал активным для VLAN 10.
   - Повторите аналогичный тест для R2 (отключите R2, проверьте, что R1 берёт на себя VLAN 20).

**2. Порядок выполнения**
1. Соберите топологию в Cisco Packet Tracer.
2. Настройте VLAN и trunk на коммутаторах.
3. Настройте подинтерфейсы на R1 и R2.
4. Настройте HSRP с балансировкой нагрузки (приоритеты, preempt, виртуальные IP).
5. Настройте ПК (IP-адреса и шлюзы).
6. Проверьте работу HSRP (`show standby brief`).
7. Проведите тестирование отказоустойчивости.
8. Оформите отчёт.

### Вариативная часть

*(Выполняется по выбору студента или по указанию преподавателя)*

**Вариант А.** Добавьте третий VLAN (VLAN 30) и настройте HSRP так, чтобы активным для него стал R1. Проверьте распределение нагрузки между тремя VLAN (R1 — VLAN 10 и 30, R2 — VLAN 20).

**Вариант Б.** Используйте **две группы HSRP для одного VLAN** (например, группа 10 и группа 110). Настройте DHCP-сервер так, чтобы половина клиентов получала шлюз `192.168.10.254` (группа 10, активный R1), а другая половина — `192.168.10.253` (группа 110, активный R2). Это более тонкая балансировка в пределах одного VLAN.

**Вариант В.** Настройте **HSRP-трекинг (tracking)** для отслеживания состояния вышестоящего интерфейса (например, интерфейса в сторону внешней сети). При его падении приоритет HSRP должен снижаться, чтобы трафик переключился на резервный маршрутизатор.

**Вариант Г.** Вместо маршрутизаторов используйте **коммутаторы L3** (например, Cisco 3560). Настройте HSRP на интерфейсах SVI (VLAN 10 и VLAN 20). Сравните конфигурацию с вариантом на маршрутизаторах.
