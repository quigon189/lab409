## Цель работы
- **Теоретическая:** Изучить расширенные возможности протокола OSPFv2 в пределах одной области (Area 0): аутентификация MD5, пассивные интерфейсы, управление метрикой (cost), изменение типа сети, редистрибуция статических маршрутов, настройка таймеров Hello/Dead.
- **Практическая:** Приобрести навыки настройки и анализа расширенных функций OSPFv2 в Cisco Packet Tracer, оценки влияния этих функций на выбор маршрута, безопасность и стабильность работы протокола.

## Теоретическая справка

**1. Основные расширенные функции OSPFv2:**
- **Аутентификация MD5** — более безопасный метод по сравнению с clear-text. Пароль не передаётся в открытом виде, используется хеш-функция. Настраивается на интерфейсе (`ip ospf message-digest-key <id> md5 <пароль>`) и в процессе OSPF (`area 0 authentication message-digest`).
- **Пассивные интерфейсы (`passive-interface`)** — интерфейсы, на которых OSPF не отправляет Hello-пакеты, но сеть продолжает анонсироваться в LSDB. Применяются для LAN-интерфейсов, подключённых к конечным устройствам, чтобы избежать лишнего служебного трафика и повысить безопасность.
- **Управление метрикой (cost)** — метрика OSPF рассчитывается как `Reference BW / Interface BW`. Можно вручную задать cost на интерфейсе командой `ip ospf cost <значение>`. Это позволяет влиять на выбор маршрута при наличии нескольких путей равной длины.
- **Изменение типа сети** — по умолчанию Ethernet-интерфейсы имеют тип `broadcast` (выбираются DR/BDR). Можно изменить на `point-to-point` командой `ip ospf network point-to-point`, что исключает выбор DR/BDR и ускоряет сходимость.
- **Редистрибуция статических маршрутов** — позволяет импортировать в OSPF маршруты, полученные из других источников (статические, подключённые, из других протоколов). Выполняется командой `redistribute static subnets` в процессе OSPF. При этом генерируются LSA Type 5 (External LSA).
- **Таймеры Hello/Dead** — по умолчанию Hello = 10 с, Dead = 40 с. Можно изменить на интерфейсе (`ip ospf hello-interval`, `ip ospf dead-interval`). Таймеры должны совпадать на обоих концах линка, иначе соседство не установится.

**2. Ключевые команды:**
- Аутентификация MD5:
  ```
  interface g0/0
   ip ospf message-digest-key 1 md5 SECRET_PASS

  router ospf 1
   area 0 authentication message-digest
  ```
- Пассивный интерфейс:
  ```
  router ospf 1
   passive-interface g0/2
  ```
- Управление cost:
  ```
  interface g0/1
   ip ospf cost 100
  ```
- Изменение типа сети:
  ```
  interface g0/1
   ip ospf network point-to-point
  ```
- Редистрибуция статики:
  ```
  ip route 203.0.113.0 255.255.255.0 Null0
  router ospf 1
   redistribute static subnets
  ```
- Таймеры:
  ```
  interface g0/0
   ip ospf hello-interval 5
   ip ospf dead-interval 20
  ```
- Проверка:
  - `show ip ospf neighbor` — соседство;
  - `show ip ospf interface <int>` — тип сети, таймеры, аутентификация;
  - `show ip ospf database` — LSDB (типы LSA);
  - `show ip route ospf` — маршруты OSPF.

## Задание

### 1. Обязательная часть

**1. Построение топологии:**
- Разместите 4 маршрутизатора (R1–R4) и 4 ПК (PC1–PC4).
- Соедините маршрутизаторы в кольцо Ethernet-линками:
  - R1 G0/0 ↔ R2 G0/0 (сеть 10.0.12.0/30);
  - R2 G0/1 ↔ R3 G0/0 (сеть 10.0.23.0/30);
  - R3 G0/1 ↔ R4 G0/0 (сеть 10.0.34.0/30);
  - R4 G0/1 ↔ R1 G0/1 (сеть 10.0.41.0/30).
- Подключите ПК к LAN-интерфейсам:
  - PC1 → R1 G0/2 (192.168.1.0/24);
  - PC2 → R2 G0/2 (192.168.2.0/24);
  - PC3 → R3 G0/2 (192.168.3.0/24);
  - PC4 → R4 G0/2 (192.168.4.0/24).
- На R1 создайте Loopback0 с адресом `203.0.113.1/24` (эмуляция внешней сети).
- На каждом маршрутизаторе создайте Loopback1 с адресом `X.X.X.X/32` (X = 1,2,3,4) для Router ID.

**2. Базовая IP-адресация:**

**3. Базовая настройка OSPF (Area 0):**
- На каждом маршрутизаторе настройте OSPF процесс 1, Router ID из Loopback1, и включите все сети (кроме внешней 203.0.113.0/24) в Area 0:
  ```
  ! Пример для R1
  router ospf 1
   router-id 1.1.1.1
   network 10.0.12.0 0.0.0.3 area 0
   network 10.0.41.0 0.0.0.3 area 0
   network 192.168.1.0 0.0.0.255 area 0
   network 1.1.1.1 0.0.0.0 area 0
  ```
  (Аналогично для R2, R3, R4 с их сетями.)
- Убедитесь, что соседство установлено (`show ip ospf neighbor`), и все маршруты доступны.

**4. Настройка аутентификации MD5:**
- На R1, R2, R3 и R4 на интерфейсах G0/0, G0/1:
  ```
  interface g0/0
   ip ospf message-digest-key 1 md5 SECRET_PASS
  ```
- В процессе OSPF на R1, R2, R3 и R4:
  ```
  router ospf 1
   area 0 authentication message-digest
  ```
- Проверьте, что соседство не потерялось. Попробуйте изменить пароль на R2 — соседство должно разорваться, а после возврата — восстановиться.

**5. Настройка пассивных интерфейсов:**
- На всех маршрутизаторах настройте LAN-интерфейсы (G0/2) как пассивные:
  ```
  router ospf 1
   passive-interface g0/2
  ```
- Проверьте, что Hello-пакеты не отправляются в сторону ПК, но сеть 192.168.X.0/24 продолжает анонсироваться (см. `show ip ospf interface g0/2` — должно быть `No Hellos (Passive interface)`).

**6. Управление метрикой (cost) для выбора пути:**
- Изначально в кольце от R2 до R4 есть два пути: R2–R1–R4 и R2–R3–R4. По умолчанию cost на всех Ethernet-линках одинаков (1 при reference bandwidth 100 Мбит/с, но в CPT скорости могут быть 1 Гбит/с, тогда cost = 1). Чтобы сделать путь через R3 предпочтительным, увеличьте cost на линке R2–R1 и R4–R1:
  - На R2 интерфейс G0/0 (к R1): `ip ospf cost 100`
  - На R4 интерфейс G0/1 (к R1): `ip ospf cost 100`
- Проверьте таблицу маршрутизации на R2 до сети 192.168.4.0/24 (LAN R4). Выполните `traceroute` с PC2 до PC4. Убедитесь, что трафик идёт через R3 (R2 → R3 → R4).
- Объясните, как cost влияет на выбор маршрута.

**7. Редистрибуция статического маршрута во внешнюю сеть:**
- На R1 создайте статический маршрут в Null0 для сети 203.0.113.0/24:
  ```
  ip route 203.0.113.0 255.255.255.0 Null0
  ```
- В процессе OSPF на R1 выполните редистрибуцию:
  ```
  router ospf 1
   redistribute static subnets
  ```
- Проверьте на R2, R3, R4 появление маршрута 203.0.113.0/24 как внешнего OSPF (E2). Выполните `show ip route ospf` и `show ip ospf database` — найдите LSA Type 5.

**8. Настройка таймеров Hello/Dead на линке R1–R2:**
- На R1 и R2 на интерфейсе G0/0 установите:
  ```
  ip ospf hello-interval 5
  ip ospf dead-interval 20
  ```
- Убедитесь, что соседство установилось (таймеры должны совпадать). Затем измените на R2 hello на 10, dead на 40 — соседство должно разорваться. Верните значения 5/20.

**9. Проверка LSDB и связности:**
- На R1 выполните `show ip ospf database` — найдите LSA Type 1, Type 2, Type 5. Обратите внимание на Router ID и содержимое.
- Проверьте сквозную связность: PC1 → PC4, PC1 → 203.0.113.1. Выполните `tracert` и зафиксируйте пути.

**4.2. Порядок выполнения**
1. Соберите топологию, настройте IP-адресацию и базовый OSPF.
2. Настройте MD5-аутентификацию на R1–R2 и в зоне 0.
3. Настройте пассивные интерфейсы на LAN.
4. Измените cost на R2 G0/0 и R4 G0/1, проверьте изменение пути.
5. Настройте редистрибуцию статического маршрута на R1.
6. Настройте таймеры Hello/Dead на R1–R2, проверьте влияние на соседство.
7. Проанализируйте LSDB, проверьте связность.
8. Оформите отчёт.
