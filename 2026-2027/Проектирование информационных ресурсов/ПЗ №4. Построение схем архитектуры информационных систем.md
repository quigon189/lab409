## Теория

**Архитектура ИС** — описание структуры системы: из каких компонентов она состоит, как они взаимодействуют и по каким правилам.

**Основные понятия:**
- **Клиент** — компонент, запрашивающий данные (браузер, приложение).
- **Сервер** — компонент, обрабатывающий запросы и возвращающий результат.
- **Уровень представления** — отображение данных пользователю (HTML, CSS, JS).
- **Уровень логики** — обработка данных, бизнес-правила (PHP, Python, Java, Node.js).
- **Уровень данных** — хранение данных (MySQL, PostgreSQL, MongoDB).
- **Монолит** — вся система в одном приложении: интерфейс, логика и данные вместе.
- **SPA (Single Page Application)** — клиентская часть загружается один раз, данные подгружаются через API без перезагрузки страницы.

**Шаг 1. Определите состав компонентов.**

**Шаг 2. Постройте схему в draw.io.**  
Изобразите компоненты прямоугольниками, связи — стрелками. Покажите, что уровни представления, логики и данных находятся **внутри одного приложения**. Обязательно подпишите:

- названия компонентов;
- границы монолитного приложения (пунктирная рамка).

**Шаг 3. Проверьте схему.**

- стрелки показывают направление взаимодействия;
- видно, что уровни представления, логики и данных объединены в одном приложении.

**Шаг 4. Заполните описание по шаблону.**

### Часть 2. Схема SPA-архитектуры

**Шаг 5. Определите состав компонентов.**  
В SPA-архитектуре клиентская часть отделена от серверной логики. Определите компоненты:
- клиент (браузер с SPA-приложением);
- веб-сервер (раздача статики);
- API-сервер (серверная логика);
- база данных.

**Шаг 6. Постройте схему в draw.io.**  
Изобразите компоненты и связи. Покажите:
- что SPA-приложение загружается один раз и работает на клиенте;

- что уровень представления находится **на клиенте**, а уровень логики — **на сервере**.

**Шаг 7. Проверьте схему.**  
Убедитесь, что:
- отражено разделение клиентской и серверной частей;
- показаны API-запросы и ответы;
- подписаны форматы обмена (JSON).
