## Цель и задачи занятия

**Основная цель:** освоить синтаксис Markdown и научиться оформлять техническую документацию в этом формате — как основу подхода Doc as Code.

**Задачи:**
- изучить базовый синтаксис Markdown (заголовки, форматирование текста, списки, ссылки, изображения, таблицы, код);
- научиться работать в онлайн-редакторе StackEdit с предпросмотром;
- отработать навык оформления технического документа в Markdown;
- подготовить основу для ведения документации в репозитории (связь с лекцией о Doc as Code).

---

## Теоретический минимум

### 1. Что такое Markdown и зачем он нужен

**Markdown** — это лёгкий язык разметки, который позволяет оформлять текст с помощью простых символов (решёток, звёздочек, дефисов) и при этом оставаться **читаемым в исходном виде**.

**Главная идея:** обычный текст + минимальная разметка = документ, который можно:
- читать как есть (без рендеринга);
- легко сравнивать в Git (видно, что изменилось построчно);
- конвертировать в HTML, PDF, DOCX;
- публиковать на GitHub, в вики, на сайтах документации.

**Зачем Markdown веб-разработчику:**
- это стандарт оформления `README.md` на GitHub;
- основа подхода **Doc as Code**;
- используется в документации API;
- применяется в Jira, Trello, Notion;
- на нём пишутся статьи, инструкции, комментарии.

**Файлы Markdown** имеют расширение `.md`.

---

### 2. Знакомство со StackEdit

**StackEdit** (https://stackedit.io/) — бесплатный онлайн-редактор Markdown, который работает в браузере. Не требует установки и регистрации.

**Как устроен интерфейс:**
- **Слева** — панель файлов и меню.
- **В центре** — область редактирования (сюда вы набираете текст).
- **Справа** — предпросмотр (здесь сразу видно результат).

**Основные действия:**
- **Создать новый файл:** меню слева → иконка «+» → «New file».
- **Переименовать файл:** клик по названию файла в левой панели.
- **Экспорт:** меню (три точки вверху справа) → «Export» → «Export as Markdown» (скачать `.md`) или «Export as HTML» / «PDF».
- **Сохранение:** StackEdit хранит файлы в браузере автоматически. Для надёжности используйте экспорт в `.md`.

> **Важно:** работайте **только** в StackEdit. Все задания выполняются в этом редакторе.

### 3. Базовый синтаксис Markdown (краткий справочник)

| Элемент              | Синтаксис                              | Пример результата     |
| -------------------- | -------------------------------------- | --------------------- |
| Заголовок 1          | `# Текст`                              | Крупный заголовок     |
| Заголовок 2          | `## Текст`                             | Подзаголовок          |
| Заголовок 3          | `### Текст`                            | Под-подзаголовок      |
| Жирный               | `**текст**`                            | **текст**             |
| Курсив               | `*текст*`                              | *текст*               |
| Зачёркнутый          | `~~текст~~`                            | ~~текст~~             |
| Код в строке         | `` `код` ``                            | `код`                 |
| Маркированный список | `- пункт`                              | • пункт               |
| Нумерованный список  | `1. пункт`                             | 1. пункт              |
| Чек-лист             | `- [x] готово`                         | ☑ готово              |
| Ссылка               | `[текст](url)`                         | текст (кликабельно)   |
| Изображение          | `![alt](url)`                          | картинка              |
| Цитата               | `> текст`                              | цитата                |
| Блок кода            | ```` ```js ... ``` ````                | блок с подсветкой     |
| Таблица              | `\| a \| b \|` + строка `\|---\|---\|` | таблица               |
| Линия                | `---`                                  | горизонтальная линия  |
| Экранирование        | `\*текст\*`                            | *текст* (без курсива) |

### Шаг 6. Итоговый документ `README.md`

Создайте **новый файл** в StackEdit и назовите его `README.md`. Это документация для вашего учебного проекта.

**Тему проекта выберите самостоятельно:** например, «Сайт кофейни», «Портал онлайн-курсов», «Интернет-магазин», «Личный блог». Далее — заполняйте по шаблону **своим** содержанием, но с обязательным использованием разметки.

**Структура документа (обязательные элементы):**

#### 1. Заголовок H1
Название проекта.  
**Пример:** `# Сайт кофейни «Утро»`

#### 2. Краткое описание (2–3 предложения)
С элементами форматирования — хотя бы одно слово жирным, одно курсивом.  
**Пример:** `Проект представляет собой **корпоративный сайт** кофейни с меню, фотогалереей и формой обратной связи. Основная цель — *привлечь новых клиентов* и рассказать о преимуществах заведения.`

#### 3. Раздел «Возможности» (H2)
Маркированный список из 4+ пунктов.  
**Пример:**
```
## Возможности

- Просмотр меню с категориями и ценами
- Фотогалерея интерьера
- Форма обратной связи
- Интерактивная карта с адресом
```

#### 4. Раздел «Технологии» (H2)
Таблица минимум с 3 столбцами и 3 строками данных.  
**Пример:**
```
## Технологии

| Технология | Назначение | Версия |
|---|---|---|
| HTML | Разметка | 5 |
| CSS | Стили | 3 |
| JavaScript | Интерактивность | ES2023 |
```

#### 5. Раздел «Установка» (H2)
Нумерованный список шагов + блок кода с командами.  
**Пример:**
```
## Установка

1. Склонируйте репозиторий
2. Перейдите в папку проекта
3. Установите зависимости

```bash
git clone https://github.com/example/coffee-site.git
cd coffee-site
npm install
```
```

#### 6. Раздел «Структура проекта» (H2)
Блок кода с деревом папок.  
**Пример:**
```
## Структура проекта

```
coffee-site/
├── index.html
├── css/
├── js/
└── images/
```

#### 7. Раздел «Планы» (H2)
Чек-лист минимум из 4 пунктов (1–2 выполненных).  
**Пример:**
```
## Планы

- [x] Свёрстан макет главной страницы
- [x] Подключены стили
- [ ] Добавлена форма обратной связи
- [ ] Настроена карта
```

#### 8. Раздел «Полезные ссылки» (H2)
Минимум 2 ссылки.  
**Пример:**
```
## Полезные ссылки

- [Документация Markdown](https://www.markdownguide.org/)
- [StackEdit](https://stackedit.io/ "Онлайн-редактор")
```
#### 9. Изображение
Логотип или картинка-заглушка.  
**Пример:** `![Логотип проекта](https://via.placeholder.com/150)`

#### 10. Цитата
Девиз или примечание.  
**Пример:** `> «Лучше меньше, да лучше» — принцип этого проекта.`

#### 11. Горизонтальные линии
Между крупными разделами (по желанию).  
**Как оформить:** `---` на отдельной строке с пустыми строками вокруг.

| Жирный курсив        | `***текст***`                   | ***текст***          |
| Зачёркнутый          | `~~текст~~`                     | ~~текст~~            |
| Код в строке         | `` `код` ``                     | `код`                |

| Вложенный пункт      | `  - пункт` (2 пробела)         | вложенный            |

| Ссылка               | `[текст](url)`                  | кликабельный текст   |
| Ссылка с подсказкой  | `[текст](url "подсказка")`      | с tooltip            |
| Изображение          | `![alt](url)`                   | картинка             |
| Цитата               | `> текст`                       | цитата               |
| Блок кода            | ```` ```js ... ``` ````         | блок с подсветкой    |
| Таблица              | `\| a \| b \|` + `\|---\|---\|` | таблица              |
| Выравнивание         | `:---`, `:---:`, `---:`         | влево, центр, вправо |
| Линия                | `---`                           | горизонтальная линия |
| Экранирование        | `\*текст\*`                     | *текст* без курсива  |
